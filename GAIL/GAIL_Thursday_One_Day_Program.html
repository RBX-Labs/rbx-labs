GAIL Thursday One-Day Prep Program

Use this as the source of truth for Thursday, July 9, 2026. The goal is not to cover everything equally. The goal is to lock the exam’s main concept buckets into memory, reduce confusion between similar terms, and finish the day with a usable review sheet.

What Success Looks Like

By the end of the day, you should be able to:

  • Define the core GAIL concepts in one sentence each.
  • Distinguish similar terms that are easy to confuse.
  • Map Google Cloud GenAI products to the problem each one solves.
  • Explain the difference between model capability, product choice, output improvement, and governance.
  • Answer practice questions by identifying the concept bucket first, then the exact answer.

Study Rules

  • Keep one running notes page only.
  • For every concept, write:
  • what it is
  • when to use it
  • what it is not
  • Do not collect extra material during the day unless it directly helps with the exam buckets.
  • If a concept feels fuzzy, force it into a simple comparison against a nearby concept.
  • Use short written recall, not passive rereading.

Core Buckets

These are the only four major GAIL buckets for the day:

  1. GenAI fundamentals
  2. Improving model output
  3. Google Cloud GenAI offerings
  4. Business strategy and governance

If a detail does not fit one of these buckets, it is secondary.

The official exam guide weights the domains approximately as follows: fundamentals 30%, Google Cloud offerings 35%, output improvement 20%, and business strategy 15%. The exam is therefore broad and scenario-oriented; it rewards choosing the right business, product, or governance response more than recalling deep configuration.

9:00–10:30 AM - GenAI Fundamentals

Goal

Build a crisp mental model of the basic terms so later questions do not blur together.

Concepts to cover

  • Models
  • Prompts
  • Tokens
  • Embeddings
  • Hallucinations
  • Grounding
  • RAG
  • Multimodal AI

What to write for each term

For each concept, write one line for:

  • definition
  • purpose
  • common trap

What each term should mean

  • Model: the system that generates predictions or responses.
  • Prompt: the input that steers the model.
  • Token: a chunk of text the model processes.
  • Embedding: a numeric representation of meaning.
  • Hallucination: a confident but incorrect model output.
  • Grounding: connecting the model to reliable external information.
  • RAG: retrieval plus generation, so the model can answer with relevant external context.
  • Multimodal AI: AI that works with more than one data type, such as text, image, or audio.

Learning approaches that can appear in scenarios

  • Supervised learning: learns from labeled examples with known answers. Think of training with an answer key.
  • Unsupervised learning: finds patterns or groups in unlabeled data. Think of discovering the categories yourself.
  • Reinforcement learning: learns by taking actions and receiving rewards or penalties.

Candidate reports also mention structured and unstructured data, Vertex AI MLOps, and the model lifecycle as recurring areas. Treat these as fundamentals, not optional technical details.

Common traps to watch for

  • Treating embeddings as answers instead of representations.
  • Treating grounding as the same thing as fine-tuning.
  • Treating RAG as a model type instead of a system pattern.
  • Treating hallucination as a bug in the prompt only.
  • Treating multimodal AI as text-only chat with attachments.

How to study

  • Make a two-column sheet:
  • left side: concept
  • right side: definition plus trap
  • Test yourself by covering the right side and reciting the answer.
  • Compare close pairs:
  • grounding vs RAG
  • prompt vs model
  • embeddings vs tokens
  • multimodal vs text-only

Checkpoint question

  • If you saw a question asking how to reduce hallucinations by using external sources, would you choose grounding, RAG, fine-tuning, or a larger prompt? Explain why.

Output by 10:30 AM

  • Short definitions for all fundamentals
  • A list of confusion pairs
  • A mini recall sheet you can drill later

10:45 AM–12:00 PM - Improving Model Output

Goal

Understand how to make model responses better through prompting, structure, and validation.

Concepts to cover

  • Prompting
  • Constraints
  • Evaluation
  • Human review
  • Feedback loops
  • Prompt chaining
  • Critique/refine
  • Gate checks
  • Prompt templates
  • Saved info and Gems
  • Metaprompting
  • Sampling parameters

What each concept means in practice

  • Prompting: asking the model in a way that increases the chance of a useful answer.
  • Constraints: limits on format, tone, scope, length, or behavior.
  • Evaluation: checking whether the result meets the task requirement.
  • Human review: a person validates or corrects the output.
  • Feedback loop: using the result of one step to improve the next step.
  • Prompt chaining: continuing a conversation so context carries forward, or splitting one task into multiple ordered prompts in a production workflow. Use the scenario wording to identify which meaning is intended.
  • Critique/refine: produce a draft, then review and improve it.
  • Gate check: validate quality before moving to the next stage.
  • Prompt templates: saved prompts for repeated tasks, formats, and instructions.
  • Saved info in Gemini: specific facts or preferences stored for consistent use.
  • Gems: personalized Gemini assistants that follow specific instructions for recurring templates, prompts, and guided workflows.
  • Metaprompting: using prompts to generate, modify, critique, or interpret other prompts.
  • Sampling parameters: settings that tune model behavior, including token count, temperature, top-p, safety settings, and output length.

How to practice

  • Take 5 vague user requests and rewrite them into strong prompts.
  • For each rewrite, add:
  • role
  • task
  • constraints
  • output format
  • success criteria
  • Then ask:
  • what could still go wrong?
  • what should be checked before using the result?

Output improvement pattern

Use this sequence:

  1. State the task clearly.
  2. Add constraints.
  3. Ask for structured output.
  4. Check the result against the requirement.
  5. Refine if needed.

Common traps

  • Thinking better prompting alone solves every output problem.
  • Confusing evaluation with generation.
  • Confusing critique/refine with a single-pass prompt.
  • Assuming a model will self-correct without a validation step.

Scenario lens

  • Need the model to use current, trusted facts -> use grounding; RAG is one common retrieval-plus-generation implementation.
  • Need the model to learn a durable behavior or format from training examples -> consider tuning, not just retrieval.
  • Need a person to approve a consequential answer -> use human-in-the-loop review.
  • Need a reusable prompt for the same recurring task -> save a template; need a personalized Gemini workflow -> use saved info or a Gem.
  • Need to improve the prompt itself -> use metaprompting.

RAG and sampling detail

RAG follows a repeatable workflow:

  1. Retrieve relevant information from external sources with tooling.
  2. Augment the prompt with that information.
  3. Generate a response from the augmented prompt.
  4. Iterate retrieval if more information is needed.

Sampling controls change behavior, not factual grounding:

  • Token count: meaningful chunks of text the model processes.
  • Temperature: controls creativity or randomness in word choice.
  • Top-p: limits the cumulative probability range of likely next tokens considered.
  • Safety settings: filter potentially harmful or inappropriate output.
  • Output length: sets the maximum generated response length.

Checkpoint question

  • When should you use prompt chaining instead of one large prompt?

Output by 12:00 PM

  • A rewritten prompt set
  • A list of output-improvement patterns
  • A simple validation checklist

1:00–2:15 PM - Google Cloud GenAI Offerings

Goal

Map products to use cases so the exam answers feel obvious instead of memorized.

Product naming rule

The exam was recently updated to reflect branding changes. When an answer choice uses a current exam-guide term, use that term. The current guide uses Agent Platform, Agent Search, and Agent Studio. Older study materials, candidate reports, and course content may still say Vertex AI, Vertex AI MLOps, or Agent Builder. Those are useful related labels, but they must not override the current exam-guide wording.

Concepts to cover

  • Gemini
  • Vertex AI (related study-guide term)
  • Model Garden
  • Agent Studio (called Agent Builder in older materials)
  • Gemini for Google Workspace
  • Enterprise search and grounding features
  • Google AI Studio and Vertex AI Studio
  • Gemini for Google Cloud
  • NotebookLM
  • MLOps and lifecycle management (often called Vertex AI MLOps in older material)
  • TPUs and GPUs

What to know for each item

  • Gemini: Google’s multimodal generative AI model family. It can support text, images, code, and other modalities; it is a specific model family, not the generic definition of all generative AI.
  • Gemini app: the multimodal assistant experience that people use directly. A question can call the model family “Gemini” and separately call the user-facing assistant “the Gemini app”; identify which layer the option describes.
  • Agent Platform: formerly Vertex AI, Google Cloud’s unified ML platform for building, training, tuning, deploying, and managing ML models and AI applications. Agents are one use of the platform, not its whole scope.
  • Model Garden: the place to discover and use available models.
  • Agent Studio: the current exam-guide term for tooling that builds and manages agentic experiences and workflows. Older material may call this Agent Builder.
  • Gemini for Google Workspace: AI assistance inside productivity apps.
  • Enterprise search and grounding: ways to connect AI answers to enterprise data.
  • Google AI Studio: a fast prototyping environment for trying prompts and model behavior.
  • Vertex AI Studio: a production-oriented environment for building and deploying AI applications at scale.
  • Gemini for Google Cloud: an assistant for cloud development, operations, data, and security work.
  • NotebookLM: a document-grounded research assistant that works from supplied sources.
  • MLOps and lifecycle management: practices and tooling for versioning, monitoring, evaluating, and improving models after launch. Older material may call this Vertex AI MLOps.
  • TPUs and GPUs: specialized infrastructure that accelerates the calculations used to train and serve AI.

The key distinction is layer: Gemini is the model family; the Gemini app is the assistant experience; Agent Platform is the unified managed ML platform; Model Garden is the catalogue for choosing models inside that platform; and Agent Studio is for designing agent experiences. Scenario questions often describe the business need first, then test whether you can choose the correct layer and current product label.

High-value wording traps from course-style questions

  • “Gen AI is only chatbots” -> false. The business value includes new text, code, images, audio, video, and other generated content. A photorealistic product-prototype image from a text description is a clear non-chatbot example.
  • “Automates repetitive tasks” or “finds patterns and predicts” -> may describe automation or predictive ML, but not the defining feature of generative AI. The defining feature is creating new content.
  • “Multimodal” -> the application combines or works across more than one data type. Analyzing video testimonials and written surveys together is multimodal; summarizing one report, drafting one email, or making one image is not automatically multimodal.
  • Foundation model versus LLM multiple-select -> select both “all LLMs are foundation models” and “LLMs are a specialized type of foundation model.” Do not select “all foundation models are LLMs”: a foundation model can specialize in images, audio, video, code, or multiple modalities rather than language alone.
  • Gemini multiple-select wording -> a correct statement can identify Gemini as Google’s generative AI model family, while another can correctly identify the Gemini app as a multimodal assistant. Reject options that define Gemini as all generative AI, only a chatbot, or an image-only model.
  • “Platform” wording -> Agent Platform is not only for production agents. It is the unified ML platform for the full model and AI-application lifecycle, including model access through Model Garden, tuning, deployment, evaluation, and management.

Study method

For each product, write:

  • what it is
  • what problem it solves
  • what kind of user or team would choose it
  • one common exam trap

Product mapping examples

  • Need to build and manage agents in production -> think Agent Platform.
  • Need an internal assistant in docs, mail, or spreadsheets -> think Gemini for Workspace.
  • Need to connect answers to enterprise content -> think grounding or enterprise search.
  • Need to design a structured agent experience -> think Agent Studio.

Common traps

  • Treating all Google Cloud AI products as the same layer.
  • Picking a product name when the question is actually about the function it serves.
  • Confusing model selection with application building.

Scenario lens

  • Need a capable model or direct assistant experience -> think Gemini.
  • Need to build and manage agents in production -> think Agent Platform.
  • Need enterprise facts in the answer -> think grounding or RAG, not simply a different model.

Candidate reports specifically mention Vertex AI MLOps, Google AI Studio, Gemini Enterprise, Customer Engagement Suite, Gemma, and TPUs. Treat older names as aliases, then answer with the exact current exam-guide name offered in the choices.

Checkpoint question

  • If a company wants an AI assistant connected to its internal documents, are you choosing a model, a platform, a grounding feature, or a productivity app integration?

Output by 2:15 PM

  • A product-to-purpose mapping table
  • A one-line purpose for each Google Cloud offering
  • A list of product confusion traps

2:30–3:30 PM - Business Strategy and Governance

Goal

Be able to explain why a solution is appropriate and safe, not just what the technology is.

Concepts to cover

  • Use-case selection
  • ROI
  • Privacy
  • Bias
  • Human oversight
  • Auditability
  • Change management
  • Policy alignment

What each concept means

  • Use-case selection: choosing problems where AI is actually worth applying.
  • ROI: whether the value justifies the cost and risk.
  • Privacy: protecting sensitive data and limiting exposure.
  • Bias: unfair or skewed outputs or decisions.
  • Human oversight: people remain accountable for important decisions.
  • Auditability: the system can be reviewed and traced.
  • Change management: helping teams adopt the system successfully.
  • Policy alignment: matching the solution to organizational rules and risk posture.

How to study

  • For each concept, answer:
  • why does this matter?
  • what goes wrong if it is ignored?
  • who is responsible?
  • Then practice turning technical answers into business answers.

Business framing pattern

When a question asks about governance, answer in this order:

  1. Identify the risk.
  2. Identify the control.
  3. Explain the business reason.

Common traps

  • Treating governance as only compliance paperwork.
  • Treating privacy as only a security issue.
  • Treating ROI as a vague "is this cool?" question.
  • Treating human oversight as optional for high-stakes use cases.

Leader mindset for scenarios

The exam is reported to be more scenario-led than configuration-led. Read slowly, identify the business need, and select the answer that balances value, feasibility, risk, responsible AI, and adoption. A technically impressive answer is not automatically the best business answer.

For a manager, the tested responsibility is to connect business goals, technical specialists, users, risk owners, success measures, and change management. You do not need to configure the model to choose a responsible solution.

Checkpoint question

  • If a solution exposes customer data or creates biased outputs, what governance concern should be raised first?

Output by 3:30 PM

  • A list of risks and matching controls
  • A business-language explanation for each key governance term

Exam-Day Readiness and Logistics

These points come from a candidate report and are operational guidance, not a substitute for the current Google or testing-provider instructions.

  • Complete the secure-browser installation and readiness check before exam day, not immediately before launch.

Google Cloud Implementation Crosswalk

Use this when a question asks how to implement a concept on Google Cloud. If there is no single product named below, the exam is testing a process, decision, or governance control rather than a tool name.

Scenario Selection Playbook

Use this before looking up a product name. GAIL scenarios can describe overlapping capabilities. Select the product that best matches the user's environment, the required output, and the amount of custom engineering implied by the question.

1. Where does the user do the work?

  • Gemini app -> an individual wants a general-purpose conversational assistant for writing, summarizing, translating, exploring, or creating.
  • Gemini in Gmail, Slides, Meet, or Drive -> the work stays in that named Google Workspace application: draft email, create a presentation image, summarize a meeting, or find and understand a Drive file.
  • NotebookLM Enterprise -> the answer must stay grounded in a set of supplied reports, notes, or other source material. It is a research-assistant answer, not a broad enterprise search answer.
  • Do not confuse with build tools -> Google AI Studio, Agent Studio, and Agent Platform are for prototyping or building systems, not the default answer for an employee completing a task in an existing app.

2. What must be created?

  • Imagen -> the deliverable is a high-quality generated still image from a text description.
  • Gemini in Google Slides -> create an image within a presentation workflow. The context, not only the image capability, makes it the best answer.
  • Veo -> generate video from a prompt or a still image.
  • Google Vids -> create business explainers, training videos, or customer troubleshooting tutorials.
  • Gemini Code Assist -> generate or explain code, unit tests, test cases, and code documentation. Treat its result as a developer-reviewed starting point.
  • Do not confuse -> Imagen is not video; Veo is not the simplest answer for a business tutorial workflow; a general chatbot is not the most direct coding assistant.

3. What information must ground the answer?

  • Gemini in Google Drive -> the requested file knowledge is in Drive.
  • Gemini Enterprise -> employees need an enterprise agent that reasons across connected internal knowledge wherever it is hosted.
  • Agent Search -> a built-in enterprise search or recommendation experience is needed.
  • Vertex AI RAG Engine / exam RAG APIs -> an application needs programmatic retrieval, augmentation, and generation over chosen data sources.
  • Grounding with Google Search -> the answer needs current public information.
  • Grounding with your search API -> the application must use an approved third-party or custom search endpoint.
  • Do not confuse with fine-tuning -> fine-tuning changes model behavior for a task or domain; it does not fetch current or organization-specific facts at answer time.

4. Prototype, workflow, or production agent?

  • Google AI Studio -> quickly test prompts and model behavior.
  • Agent Studio -> design an agent's instructions, tools, and workflow.
  • Agent Platform -> build, train, tune, deploy, and manage ML models and AI applications. Use it for production agents as one important workload, not as its only purpose.
  • Cloud Run or Cloud Functions -> host the application's backend logic, API, or action that an agent calls. They are infrastructure, not the AI model.
  • Apps Script or AppSheet -> automate a business process with low-code or no-code tooling.
  • Model Garden -> select and compare available Google, partner, or open models, including the right modality for text, code, images, or speech. It is a model catalogue inside Agent Platform, not an agent workflow designer.

5. Is the task generative, analytical, predictive, or prebuilt extraction?

  • Gemini in Looker -> understand product-feedback themes and sentiment in a business-intelligence setting.
  • Gemini in BigQuery -> analyze data and make reports or visuals easier to understand.
  • Vertex AI forecasting models -> predict future demand from historical time-series data.
  • Vertex AI tabular classification or anomaly-detection workflow -> detect likely fraud or another predictive classification/anomaly pattern, then monitor it.
  • Document AI -> extract, classify, process, or summarize documents such as contracts.
  • Cloud Vision, Video Intelligence, and Natural Language APIs -> use the named prebuilt capability for images, video, or text insights. Speech-to-Text, Text-to-Speech, and Translation APIs handle conversion between speech, text, voice, and languages.
  • Do not confuse -> a GenAI assistant can explain results, but it is not the most direct answer for forecasting, fraud scoring, OCR, entity extraction, or transcription.

6. Is the question about operating and protecting the system?

  • Gen AI evaluation service -> evaluate prompt or generated-output quality with defined datasets and metrics.
  • Vertex AI Model Registry -> version and track models.
  • Vertex AI Model Monitoring -> detect production drift or training-serving skew.
  • Cloud Monitoring alerting policies and notification channels -> create operational alerts and notify people or services.
  • IAM -> control access; Security Command Center -> security posture and findings; Sensitive Data Protection -> discover and protect sensitive data; Gemini or Vertex AI safety settings -> filter unsafe output.
  • No single product -> human-in-the-loop approval, fairness, accountability, change management, ROI, and SAIF are governance or operating patterns. Tools support them but do not replace the decisions.

Models, prompts, and agents

  • Model choice -> Model Garden to discover and compare Google, partner, and open models.
  • Fast prompt or model prototype -> Google AI Studio.
  • Unified ML platform -> Agent Platform (formerly Vertex AI) to build, train, tune, deploy, and manage ML models and AI applications.
  • Model access across text, code, images, and speech -> Model Garden within Agent Platform; select the model, then tune and deploy it through the platform if required.
  • Build and manage agents in production -> Agent Platform; use Agent Studio to build and shape the agent workflow.
  • Personalized repeatable Gemini workflow -> saved info and Gems in Gemini. These are not a substitute for a production agent platform.
  • Fine-tuning -> Vertex AI tuning / fine-tuning to adapt learned behavior for a task or domain. Do not use it as a substitute for current facts.
  • Prompt evaluation and output quality -> Gen AI evaluation service with a defined dataset, metrics, and where appropriate human ratings or judge-model evaluation.

Grounding, retrieval, and data

  • Enterprise-document grounding -> Agent Search for prebuilt retrieval or Vertex AI RAG Engine / exam RAG APIs for managed RAG orchestration.
  • Current public information -> Grounding with Google Search.
  • Custom or third-party search source -> Grounding with your search API.
  • First-party data -> Cloud Storage, BigQuery, databases, and search/RAG connectors, chosen for the data type and use case.
  • Embeddings-based retrieval -> Vertex AI Vector Search or managed RAG tooling.

Model operations and delivery

  • Versioning -> Vertex AI Model Registry.
  • Generative output evaluation -> Gen AI evaluation service; traditional model evaluation can also be created through Vertex AI model workflows.
  • Production ML performance, drift, or training-serving skew -> Vertex AI Model Monitoring.
  • Feature data and automated ML workflows -> Feature Store and Vertex AI Pipelines. Feature Store variants have changed over time, so follow the current exam-guide name in the options.
  • Agent backend, APIs, and application logic -> Cloud Run or Cloud Functions.
  • Low-code/no-code AI workflows -> Apps Script or AppSheet.

Prebuilt capabilities and customer experience

  • Voice input -> Speech-to-Text API; voice output -> Text-to-Speech API.
  • Multilingual content -> Translation API; preserve a formatted document layout -> Document Translation API.
  • Document extraction and processing -> Document AI API.
  • Image understanding -> Cloud Vision API; video understanding -> Cloud Video Intelligence API; sentiment, entities, and classification -> Natural Language API.
  • Customer support or contact center AI -> Customer Engagement Suite: Conversational Agents for customers, Agent Assist for human agents, Conversational Insights for interaction analysis.
  • Customer-service text responses -> Conversational AI.
  • Draft client email -> Gemini in Gmail; presentation image -> Gemini in Google Slides.
  • Marketing or design image concepts -> Imagen; video tutorials -> Google Vids.
  • Generate code, unit tests, or test cases -> Gemini Code Assist. Treat the output as a starting point that still needs developer validation.
  • Summarize a long report or article from supplied sources -> NotebookLM Enterprise.
  • Summarize reviews for product feedback and sentiment -> Gemini in Looker.
  • Generate meeting notes, decisions, and action items -> Gemini in Google Meet.
  • Turn complex data into understandable reports and visuals -> Gemini in BigQuery.
  • Predict future demand from purchase history and traffic -> Vertex AI forecasting models.
  • Find viewing patterns and recommend relevant content -> Agent Search.
  • Adapt a model to specialized molecular or scientific data -> Agent Platform model tuning.
  • Search a Drive file or ask questions about it -> Gemini in Google Drive.
  • Give employees an agent that reasons over enterprise knowledge wherever it is hosted -> Gemini Enterprise.
  • Detect potentially fraudulent transactions in a data stream -> Vertex AI tabular classification or anomaly-detection workflow, then monitor it. This is predictive ML, not a general GenAI chat use case.
  • Convert content into accessible voice, text, or translated formats -> Speech-to-Text, Text-to-Speech, and Translation APIs, selected by the required conversion direction and format.
  • Generate code documentation automatically -> Gemini Code Assist. Older material may say Codey; use the current tool name in the options. Validate generated documentation and code.
  • Review contracts and extract key information -> Document AI.
  • Analyze customer feedback and create a ticket -> Gemini in Looker or Natural Language API for analysis, then Cloud Run, Cloud Functions, an agent extension, or a ticket-system API integration to create the ticket.
  • Send automated alarms or operational notifications -> Cloud Monitoring alerting policies and notification channels.

Security and governance

  • Identity, permissions, and access -> IAM.
  • Security posture and threat findings -> Security Command Center.

Section 1 - Fundamentals of gen AI

1.1 Core gen AI concepts and use cases

  • AI: systems that perform tasks that usually require human intelligence.
  • NLP: AI focused on language understanding and generation.
  • Machine learning: models learn patterns from data instead of being hard-coded.

ML lifecycle:

  • Data preparation: clean, transform, and structure data.
  • Model training: learn from the prepared data.
  • Model deployment: make the model available for use.

  • automate

Section 3 - Techniques to improve gen AI model output

3.1 Overcoming foundation model limitations

Common limitations:

  • Data dependency: model performance depends on the quality, completeness, relevance, and accessibility of the data it learned from.
  • Knowledge cutoff: a model can lack information about events after its training period.
  • Bias: large datasets can contain bias, and model outputs can magnify even subtle bias.
  • Fairness: responsible development requires assessing whether outputs systematically disadvantage people or groups.
  • Hallucinations: outputs that are inaccurate or not based on real information.
  • Edge cases: rare or atypical situations that expose model weaknesses and create unexpected results.
  • Context window: the amount of text the model can consider at one time.
  • Fine-tuning: adapting a pre-trained or foundation model for a specific task or domain; it is not the same as grounding with current facts.

Recommended practices:

  • grounding
  • retrieval-augmented generation
  • prompt engineering
  • fine-tuning
  • human-in-the-loop review

HITL use cases:

  • Content moderation: catches harmful or context-sensitive user-generated material that automated checks can miss.
  • Sensitive applications: adds accuracy and risk controls in domains such as healthcare and finance.
  • High-risk decisions: keeps a human accountable for consequential outputs.
  • Pre-generation review: experts validate outputs before users are affected.
  • Post-generation review: people continually review outcomes and provide feedback after deployment.

Continuous monitoring and evaluation:

  • automatic model upgrades
  • key performance indicators
  • security patches and updates
  • versioning
  • performance tracking
  • drift monitoring
  • feature store usage where appropriate
  • data management
  • model organization
  • automated pipelines

Business implication:

3.2 Prompt engineering techniques

  • Zero-shot: ask directly without examples.
  • One-shot: provide one example.
  • Few-shot: provide several examples.
  • Role prompting: tell the model what role to take.
  • Prompt chaining: split work into multiple prompts.
  • Chain-of-thought prompting: ask for stepwise reasoning when appropriate.
  • ReAct prompting: combine reasoning with tool/action steps.

When to use them:

  • Zero-shot for simple, clear tasks.
  • Few-shot when format or style matters.
  • Role prompting when the tone or perspective matters.
  • Prompt chaining when the task has dependent steps.
  • Chain-of-thought or ReAct when reasoning and action need to be structured.

3.3 Grounding techniques and use cases

Grounding types:

  • First-party enterprise data: internal company data.

Grounding offerings:

Sampling controls:

  • Token count: how much content is generated.

Core Concept Reference

1) GenAI fundamentals

This is the layer where the model is doing the generating.

  • Model: the thing that produces text, code, images, or predictions based on patterns learned during training.
  • Prompt: the request or instruction you send to the model.
  • Token: a chunk of text the model processes; token count affects context length and cost.
  • Embedding: a numeric representation of meaning used for similarity, retrieval, and search.
  • Hallucination: an output that sounds plausible but is not factually correct.
  • Grounding: connecting the model to a trustworthy source so the answer stays tied to evidence.
  • RAG: retrieve relevant external information first, then generate an answer using that context.
  • Multimodal AI: a system that can work across text, images, audio, video, or documents.

How to think about this layer:

  • The model is the engine.
  • The prompt is the steering wheel.
  • The token is the unit of fuel the engine reads.
  • Embeddings are the meaning map.
  • Grounding and RAG are how you stop the system from making up answers when external truth matters.

Common exam distinction:

  • Grounding is about tethering the answer to sources.
  • RAG is the process that retrieves those sources and feeds them into generation.
  • Fine-tuning changes the model itself; grounding does not.

2) Improving model output

This is the layer where you make the answer better without changing the model.

  • Prompting: writing instructions that improve the chance of a useful response.
  • Constraints: rules that narrow scope, format, tone, or length.
  • Evaluation: checking whether the output actually meets the goal.
  • Human review: a person checks the output before it is used.
  • Feedback loop: the next step uses the previous step’s output or errors.
  • Prompt chaining: split a large task into smaller ordered prompts.
  • Critique/refine: draft first, then review and improve.
  • Gate check: do not continue until the result passes a quality bar.

How to think about this layer:

  • If the problem is "the model is capable but sloppy," the fix is usually structure, not a different model.
  • If the problem is "the answer is incomplete or inconsistent," chain the work into steps and validate each step.

Common exam distinction:

  • A longer prompt is not the same thing as a better workflow.
  • Prompt chaining is an orchestration pattern.
  • Critique/refine is a quality-control pattern.
  • Human review is a governance or assurance pattern depending on the context.

3) Google Cloud GenAI offerings

This is the layer where you choose the right product for the right job.

  • Gemini: the model family and user-facing experience for generative AI tasks.
  • Agent Platform: the current exam-guide term for building, deploying, and managing agents and AI workflows. Older study content may use Vertex AI as a related platform label; use the current exam-guide wording when it appears in the options.
  • Model Garden: the place where you discover, test, customize, and deploy models from Google, partners, and open-model options.
  • Agent Studio: the current exam-guide term for building agentic experiences and managing prompts, workflows, and connections. Older material may use Agent Builder.
  • Gemini for Google Workspace: AI assistance inside productivity apps like docs, mail, and spreadsheets.
  • Enterprise search / grounding features: ways to connect model output to enterprise content and approved sources.

How to think about this layer:

  • Ask whether the question is about the model, the platform, the app integration, or the grounding layer.
  • Product names are often distractors unless you identify the layer first.

What the official docs emphasize:

  • The platform is now described as an integrated place to build, scale, govern, and optimize enterprise agents.
  • Model Garden is the model catalog for discovery and deployment.
  • Agent Studio is where prompts and workflows are designed and tested.

Common exam distinction:

  • If the question is "what model should I use," think model selection or Model Garden.
  • If the question is "where do I build and manage agents," think Agent Platform.

This is the layer where you decide whether the solution is worth using and how to keep it safe.

Supplemental Agentic AI / AWS-Style Systems Module

This section stays separate from the core GAIL buckets on purpose. It is here to help with agentic-system reasoning, tool use, orchestration, and safety, which often appear in adjacent questions or in broader product/system discussions.

1) Model vs Agent vs Tool vs Infrastructure

These four terms are easy to blur together, so keep them in a stack:

  • Model: the part that generates language, classifications, or plans.
  • Agent: the system that uses a model plus control logic to decide what to do next.
  • Tool: a callable external capability such as an API, calculator, browser, database, or function.
  • Infrastructure: the runtime around the agent that keeps execution reliable, such as storage, permissions, queues, retries, logging, and sandboxing.

Why the distinction matters:

  • A model can answer questions without taking action.
  • An agent can choose actions and call tools.
  • A tool does one job when invoked.
  • Infrastructure makes the whole thing safe and operable.

Practical test:

  • If it only predicts text, it is a model.
  • If it decides whether to call something else, it is an agent.
  • If it performs one external action, it is a tool.
  • If it manages the environment around those actions, it is infrastructure.

2) MCP and Tool Standardization

MCP is best understood as a protocol layer for connecting agents to tools.

What it does:

  • Gives tools a common way to be discovered and called.
  • Reduces custom integration work.
  • Makes it easier to swap tools or environments without redesigning the whole system.

Why it matters:

  • Without a protocol, every tool integration is bespoke.
  • With a protocol, the agent can work with many tools in a consistent way.

Exam lens:

  • If the question is about consistent tool integration across systems, think protocol, not model capability.

3) Memory and Session State

Memory is not one thing. Break it into three useful ideas:

  • Conversation continuity: the system keeps the interaction coherent from one turn to the next.
  • Short-term efficiency: the system compresses older context so it fits into the prompt window.
  • Long-term persistence: durable facts or preferences are stored outside the model and recalled later when needed.

Patterns to remember:

  • Summarization keeps short-term memory efficient by compressing prior turns.
  • Persistent session store keeps a conversation usable over time.
  • Session ID isolation prevents one user’s data from leaking into another user’s session.

What to remember:

  • The model itself does not preserve memory.
  • The application layer must store, summarize, and retrieve state.

4) RAG and Multi-Agent Retrieval

RAG means the model is answering with help from retrieved external content instead of relying only on its internal parameters.

Why it is used:

  • To ground answers in current or domain-specific information.
  • To reduce hallucinations when external evidence is available.
  • To make the system more useful for enterprise knowledge and documents.

In multi-agent setups, retrieval is often split into roles:

  • Retrieval coordinator: decides what to fetch and where to fetch it from.
  • Specialized retrievers: search domain-specific sources or indexes with better relevance.

Routing options:

  • Content-based routing: send the request to the most relevant agent or retriever based on topic or metadata.
  • Round-robin routing: distribute requests evenly when tasks are similar.
  • Parallel dispatch: run independent tasks at the same time to reduce latency.

Why specialized retrievers help:

  • A narrow domain often needs special filters, indexes, or ranking rules.
  • A generic retriever may miss domain-specific signals.

5) Sandbox Execution

A sandbox is a controlled execution environment for code, calculations, or risky actions.

The key rule:

  • Inject all required data before execution.

Why this matters:

  • The sandbox should be deterministic and bounded.
  • It should not rely on hidden outside state.
  • It should only receive the inputs needed for the task.

Use cases:

  • Running calculations safely.
  • Testing or executing code with limited permissions.
  • Isolating untrusted actions from the main application.

Do not confuse:

  • A sandbox is not memory.
  • A sandbox is not a model.
  • A sandbox is the place where execution happens under constraints.

6) Guardrails, Kill Switches, and Leakage Prevention

Safety is a control problem, not just a prompt-writing problem.

Core protections:

  • Input guardrails: filter or validate what enters the system.
  • Output guardrails: check what leaves the system before it reaches a user or downstream tool.
  • Kill switch: an immediate stop mechanism for unsafe behavior.
  • Trusted domains: limit browsing or retrieval to approved sources.
  • Field extraction: return only the needed fields rather than raw content.

Why both input and output matter:

  • Input checks block unsafe requests or malformed data.
  • Output checks block leakage, policy violations, or bad downstream actions.

What to remember:

  • If the question is about stopping unsafe behavior quickly, think kill switch.
  • If it is about preventing sensitive data leakage, think guardrails.

7) Output Improvement Loops

These are the orchestration patterns that make model output more reliable.

Useful patterns:

  • Prompt chaining: split a task into ordered steps instead of asking everything at once.
  • Critique/refine: draft first, then evaluate and improve.
  • Gate checks: validate quality before continuing.
  • Clarifying questions: ask for missing information instead of guessing.
  • THINK-ACT-OBSERVE: reason about the task, take an action, inspect the result, and continue.

Why this matters:

  • Many real tasks are too complex for one pass.
  • Validation is often more important than raw generation.
  • A small amount of structure often improves reliability more than a longer prompt.

8) Fast Mental Map

Use this map when a question feels fuzzy:

  • Generation layer: model
  • Action layer: agent
  • Connection layer: tool protocol such as MCP
  • State layer: session store or memory
  • Grounding layer: RAG or retrieval
  • Execution layer: sandbox
  • Control layer: guardrails or kill switch
  • Orchestration layer: chaining, critique/refine, gating

9) Common Traps

  • "It can use tools" does not automatically mean it is an agent. It may just be a model with a tool wrapper.
  • "It remembers earlier turns" does not automatically mean the model has memory. The system may be storing session state.
  • "It runs code" does not mean it is safe. Ask whether it runs inside a sandbox.
  • "It returns results from documents" usually points to RAG, not fine-tuning.
  • "It blocks unsafe behavior" should make you think of guardrails or a kill switch, not prompt wording alone.

10) One-Line Exam Rule

If you are unsure, decide whether the question is about:

  • what generates,
  • what acts,
  • what connects,
  • what remembers,
  • what retrieves,
  • what executes,
  • what protects,
  • or what orchestrates.

That usually gives the right answer.
